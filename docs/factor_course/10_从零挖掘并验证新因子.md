# 第10课：从零挖掘并验证新因子

## 本课只解决一个问题

> 怎样从经济想法出发，完成因子实现、测试、实验和否定，而不是盲目枚举参数？

## 本课目标

- 写出因子假设卡；
- 实现一个不泄漏的因子；
- 写最小单元测试；
- 使用独立配置和输出目录；
- 根据证据保留或放弃因子。

## 一、先写假设，不先跑数据

```markdown
名称：downside_volatility_20
直觉：近期负收益波动很大的股票，后续风险和卖压可能更高。
定义：过去20日负收益部分的标准差。
预设方向：-1。
预测期：未来5日。
预期重复因子：volatility_20、volatility_60。
反证：样本外方向不稳、与已有波动率高度重复、成本后无改善。
```

方向和反证必须在看结果前写。

## 二、实现代码

在 `src/quant_lab/factors/library.py` 添加：

```python
def downside_volatility_20(frame: pd.DataFrame) -> pd.Series:
    require_columns(frame, ["symbol", "close"])
    price = _adjusted_close(frame)
    returns = price.groupby(frame["symbol"], sort=False).pct_change()
    downside = returns.clip(upper=0.0)
    return (
        downside.groupby(frame["symbol"], sort=False)
        .rolling(20, min_periods=15)
        .std()
        .reset_index(level=0, drop=True)
    )
```

并在 `FACTOR_REGISTRY` 注册。

## 三、必须测试什么

至少四类：

1. 两只股票不能串值；
2. 预热期应为缺失；
3. 修改未来价格不能影响过去因子；
4. 缺列或非法参数应明确失败。

测试通过只证明实现符合规则，不证明因子赚钱。

## 四、建立独立实验配置

不要覆盖基准目录。复制配置为：

```text
configs/experiments/downside_volatility_20.yaml
```

修改：

```yaml
project:
  output_dir: reports/generated/experiments/downside_volatility_20

factors:
  minimum_valid_factors: 1
  definitions:
    - {name: downside_volatility_20, direction: -1.0}
```

## 六、证据检查表

### 数据层

- 覆盖率是否充足？
- 是否有无穷大或异常集中？
- 具体股票案例是否符合定义？

### 预测层

- 方向是否符合预设？
- 逐年和近期是否稳定？
- 五分组是否大致单调？

### 独立性

- 与普通波动率相关性多高？
- 加入基准组合后是否提供增量？

### 可交易性

- 顶部换手多高？
- 成本前后差异多大？
- Top20与Top50是否同向？

### 样本外

- 多数测试折是否同向？
- 是否只在一个年份有效？
- 是否跑赢同区间基准？

## 七、三个可能结论

- **保留**：机制合理、多期稳定、提供独立信息且成本后有增量；
- **修改后重试**：覆盖、期限或实现存在明确问题，修改理由必须事先写下；
- **放弃**：方向不稳、高度重复、依赖单一年份或成本后消失。

放弃也是研究成果。

## 八、不要这样挖因子

- 批量试1至120日窗口，只报告最好一个；
- 全样本IC为负就翻方向；
- 改样本起点直到收益变正；
- 同时改因子、股票池、成本和持仓数；
- 删除失败实验；
- 看过测试期后仍称其为完全样本外。

## 九、本课毕业作业

提交：假设卡、公式和实现、测试、独立配置、覆盖率/IC/分组/相关性/样本外结果、成本前后比较、支持与反方证据，以及保留/重试/放弃结论。

## 十、闭卷自测

1. 为什么必须先写方向？
2. 新因子最先跑什么，而不是十年回测？
3. 为什么要独立输出目录？
4. 高IC但与已有因子相关0.95意味着什么？
5. 失败因子为什么也要记录？

## 最低过关标准

独立完成一个可复现因子实验，并敢于根据反方证据给出“放弃”结论。
